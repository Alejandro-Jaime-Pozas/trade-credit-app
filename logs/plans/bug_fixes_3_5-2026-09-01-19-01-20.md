# Plan — bug fixes 3/5

Logged 2026-09-01 19:01:20. Prompt: `logs/prompts/bug_fixes_3_5-2026-09-01-19-01-20.md`.

## The governing constraint

"Cancel" must send nothing. Today the Requirements page saves the template, asks the backend
what that would do to open cases, and offers to undo — so Cancel is a second write, and a user
who closes the tab mid-prompt is left with a default they never agreed to.

That cannot be fixed on the frontend alone: `GET /requirement-templates/{id}/impact/` diffs the
**stored** template against each case, so there is nothing to diff until after the write. The
fix is a backend endpoint that diffs a **proposed** list, writing nothing.

Everything else follows from that one endpoint — the credit case detail page needs exactly the
same preview to raise the same prompt (item 2).

## Item 4 + item 2 — backend

`storage/services/requirements.py`

- Extract the body of `diff_template_against_case` into `_diff_items_against_case(items, case)`,
  keyed by file type id. `diff_template_against_case` keeps its signature and delegates.
- Add `ProposedTemplateItem` (file_type, is_required, months_required) and
  `diff_file_types_against_case(file_types, case)`, so a hypothetical list can be diffed with
  the exact logic a real one uses. Defaults mirror what `updateTemplateItems` actually sends:
  `is_required=True`, `months_required=None`.

`storage/views.py`

- Pull the impact-entry building out of the `impact` action into `_impact_entries(template, diff)`
  so both actions report identically.
- New `POST /requirement-templates/{id}/preview-impact/` taking `file_type_ids`. Read-only:
  it never writes, and it re-derives the file types from the database scoped to the caller's
  organization rather than trusting the ids.

## Item 4 — frontend (`app/requirements/page.tsx`)

Invert the order: preview, then write.

1. Save clicked → `previewTemplateImpact({ template, fileTypeIds })`.
2. No entries → save immediately, done. (Also the path when no template exists yet: nothing can
   be seeded from a template that isn't there.)
3. Entries → hold the selection in state and show the prompt. Nothing has been written.
   - Update these cases → save the template, then apply to the listed cases.
   - Keep them as they are → save the template only.
   - **Cancel → drop the held selection. Zero requests.**

`previousFileTypeIds` and the undo path go away entirely.

## Item 2 — frontend (`app/credit-cases/[id]/page.tsx`)

Requirement edits stop being applied per click and become a draft:

- `pendingAddIds` / `pendingRemoveKeys`, rendered inline (`+ New` and struck-through `Removing`,
  each with Undo) so the user sees the shape of the change before committing.
- Done with no pending edits → leaves edit mode. No request, no prompt.
- Done with pending edits → previews the resulting list against the org template and shows
  `ImpactWarning`:
  - **Update all** — apply the draft to this case, make the list the org default, and apply it
    to the other open cases.
  - **Only this case** — apply the draft to this case alone.
  - **Cancel** — closes the prompt and leaves the draft on screen, untouched and unsent.
- The case being edited is filtered out of the preview entries: it is handled directly, so
  listing it would double-count it.

`ImpactWarning` gains optional `title` / `intro` / `applyLabel` / `keepLabel` props. Defaults
keep the Requirements page byte-identical.

## Item 3 — backend (`storage/views.py`)

`UploadDocumentViewSet` has `create` and `perform_destroy` but no `perform_update`, so a manual
relabel is the one path into the requirement checklist that never recomputes the case.

Add `perform_update` calling `handle_manual_requirement_change` — the same helper
`perform_destroy` uses, and the right one: a person relabelling a document is a direct decision
about one case, so it may move the case forward *or* pull it back.

The case is captured **before** the save, because `credit_case` is a writable field: a PATCH can
move a document between cases, and both ends need recomputing.

## Item 1 — frontend (`components/DocumentList.tsx`)

Cap the list and scroll it — but the rows contain `FileTypeSelect`, whose dropdown is an
absolutely-positioned child, and `overflow-y-auto` on an ancestor clips it. That would break
the correction control this same bug file is trying to fix in item 3.

So `FileTypeSelect` moves its panel into a portal positioned `fixed` against the trigger,
copying `TableColumnHeader.tsx`, which already solved this for the same reason (the table's
`overflow-x-auto` wrapper was slicing the leftmost filter panel). Then the scroll cap is safe.

The cap applies from `SCROLL_AFTER = 6` documents so short lists get no scrollbar at all.
