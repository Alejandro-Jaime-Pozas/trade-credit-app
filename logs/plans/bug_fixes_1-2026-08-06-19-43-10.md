# Bug fix batch 1 — `docs/bug_fixes/1/1.md`

## Context

Four defects reported against the running dev app (3 frontend, 1 backend). I traced each to a
concrete cause by reading the code and probing the live backend on `localhost:8000`. The goal is a
working signup entry point, a keyboard-usable customer combobox on the new-credit-case flow,
readable money in the credit cases table, and document upload that works from the Customer detail
page (not just the Credit Case detail page).

Per `ai/execution_context/feature_context.md`, work is logged under `logs/prompts/`,
`logs/plans/`, `logs/implementations/` as `bug_fixes_1-<yyyy-mm-dd-hh-mm-ss>.md`.

Probed the live backend (frontend dev server is not running — curl to `:3000` returns `000`):

Also found: `frontend/.next` is a stale build from Jun 13 that still contains the removed
`dashboard` route; `npx tsc --noEmit` fails on `.next/types/validator.ts` for that reason.

## 1. Signup buttons not working

**Files:** `frontend/src/components/AppShell.tsx`, `frontend/src/app/signup/page.tsx`,
`frontend/src/app/login/page.tsx`, `frontend/src/lib/auth.tsx`, `frontend/src/lib/api.ts`,
`backend/app/mixins.py`, `backend/identity/views.py`

Both "Sign up" affordances are plain `<Link href="/signup">` — the header pill
(`AppShell.tsx:74-79`) and the inline link (`login/page.tsx:88-90`) — and `/signup` exists. There is
**no** deterministic navigation bug I can prove statically, and there is **zero** `console.*` logging
anywhere in `frontend/src`, so nothing about the failure is currently observable. So: fix the two
proven defects on the signup path, remove the dead-looking button, add observability, then reproduce.

1. **Backend — stop `UserViewSet` 500ing.** In `OrganizationScopedMixin.get_queryset`, return
   `queryset.none()` when `not user.is_authenticated` (guard before the `is_superuser` /
   `user.organizations` access). This mixin is used by every viewset, so the guard is a one-place fix.
2. **Backend — narrow `AllowAny`.** Replace the blanket `permission_classes = [AllowAny]` on
   `UserViewSet` with a `get_permissions()` that returns `AllowAny` only for `action == "create"`
   and `IsAuthenticated` otherwise. This is the `TODO` already written on
   `backend/identity/views.py:22`. Signup (`POST /users/`) stays public; `GET /users/{id}/` — the
   third call in `auth.tsx`'s signup chain — requires the token it already sends.
3. **Frontend — remove the no-op button.** `AppShell` already imports `usePathname`. Hide the
   header "Sign up" pill when `pathname === "/signup"` and the "Log in" pill when
   `pathname === "/login"`. On `/signup` that pill currently re-navigates to the page you're on,
   which reads exactly as "the signup button does nothing".
4. **Frontend — make failures visible.** Add a small `logError(context, err)` helper in
   `frontend/src/lib/api.ts` (or a new `lib/log.ts`) and call it from the `catch` blocks in
   `login/page.tsx`, `signup/page.tsx`, and `AuthProvider`'s silent
   `catch { clearStoredTokens(); }` (`lib/auth.tsx:79-81`). In `apiJson`/`apiForm`, convert a
   thrown `TypeError: Failed to fetch` into an `ApiError` with a usable message naming the API base
   URL (e.g. `Cannot reach API at http://localhost:8000/api/v1`) — `getApiBaseUrl()` already exists
   at `api.ts:88-93`. There is no `NEXT_PUBLIC_API_BASE_URL` set anywhere, so the localhost fallback
   is always in play and worth naming in the error.
5. **Clear the stale build.** `frontend/.next` must be deleted so dev/build stop carrying the removed
   `dashboard` route. **This is a delete — I will ask for explicit approval before running it**, per
   `CLAUDE.md`.
6. **Reproduce.** Start both servers and click both buttons. If navigation still fails after the
   above, step 4's logging pinpoints it and I fix the actual cause then rather than guessing now.

## 2. Customer combobox has no keyboard support

**File:** `frontend/src/app/credit-cases/new/page.tsx:206-262`

The dropdown is hand-rolled (the frontend has zero UI deps — only `next`, `react`, `react-dom`, so
no library is being added). The input has **no `onKeyDown` at all**, and every option is a
`<button>` wired to `onMouseDown` only — so Enter on a focused option does nothing and Tab blurs the
input, which fires the `setTimeout(… , 150)` teardown and unmounts the list out from under focus.

- Build one `options` array = `filteredCustomers` (already memoized at lines 66-76) plus a trailing
  `{ kind: "create" }` sentinel, so index math lives in one place and the existing
  `handleSelectExisting` / `handleStartCreate` (lines 80-93) are reused unchanged.
- Add `activeIndex` state; reset to `0` whenever `search` changes or the dropdown opens.
- Add `onKeyDown` on the input: `ArrowDown`/`ArrowUp` move `activeIndex` with wraparound
  (`preventDefault` so the caret doesn't jump), `Enter` commits the active option
  (`preventDefault`), `Tab` commits the active option then lets focus continue, `Escape` closes the
  dropdown without selecting.
- Highlight the active row and set `activeIndex` on `onMouseEnter` so mouse and keyboard agree.
  Keep `onMouseDown` for click selection (it must stay ahead of the blur).
- Replace the `setTimeout` blur hack with a wrapper-level `onBlur` that checks
  `e.relatedTarget` containment, so focus moving into the list doesn't close it.
- ARIA: `role="combobox"` + `aria-expanded` + `aria-controls` + `aria-activedescendant` on the
  input; `role="listbox"` on the container and `role="option"` + `aria-selected` + stable `id` on
  each row.

## 3. REQUESTED column is not comma-formatted

**Files:** new `frontend/src/lib/format.ts`; `frontend/src/app/credit-cases/page.tsx:186-188`

`requested_amount` is a DRF decimal serialized as a **string** (`lib/api.generated.ts:574-576`) and
nullable, and it is interpolated raw → `MXN 1500000.00 / 30d`. **No currency/number formatting
utility exists anywhere in the frontend** (no `Intl.`, `NumberFormat`, `formatCurrency`, `toFixed`
hits), so one gets created.

- `formatMoney(amount: string | number | null | undefined, currency?: string | null): string` using
  `Intl.NumberFormat("es-MX", { style: "currency", currency, currencyDisplay: "code",
  minimumFractionDigits: 2 })`. Returns `"—"` for null/blank/NaN; falls back to plain grouped
  decimal + the raw currency string if the currency code is unknown (`Intl` throws on bad codes).
  Renders `MXN 1,500,000.00` — keeps the explicit ISO code that's shown today rather than switching
  to the `MX$` symbol.
- Update the cell to `{formatMoney(cc.requested_amount, cc.currency)} / {cc.requested_term_days}d`.
- While the file is being created, move the **three duplicated `formatDate` copies** into it and
  reuse: `credit-cases/page.tsx:17-22`, `credit-cases/[id]/page.tsx:21-26`,
  `customers/[id]/page.tsx:18-23`, plus the inline `toLocaleString()` at `customers/page.tsx:121`.

## 4. Backend: document upload fails from the Customer detail page

**Files:** `backend/storage/services/db_object_handling.py`, `backend/storage/views.py`,
`backend/storage/serializers.py`, `backend/integrations/openai/services/gpt.py`

The Customer page sends the right payload — `file` + `customer`, no `credit_case`
(`customers/[id]/page.tsx:239-246`) — and the model allows it: both `customer` and `credit_case` FKs
are `null=True, blank=True` (`storage/models.py:88-103`), and no migration is needed. The row is
created; the request then **500s in the post-save side effect**:

- `storage/views.py:46` calls `handle_upload_document_created(doc)` unguarded, and
  `db_object_handling.py:46-47` raises `ValueError('UploadDocument must have a related CreditCase obj.')`
  when `doc.credit_case` is `None`. → uncaught → HTTP 500, surfaced as generic "Upload failed".
- Two more latent crashes on the same path once that guard is relaxed:
  `gpt.py:274` dereferences `doc.credit_case.missing_file_type_names`, and
  `db_object_handling.py:244` does `customer = doc.credit_case.customer` inside
  `promote_csf_fields_to_customer`.

Fixes:

1. `handle_upload_document_created`: require **either** `credit_case` **or** `customer`; resolve
   `customer = doc.customer or (doc.credit_case.customer if doc.credit_case else None)`. Keep running
   the GPT extraction — `GPTService.__init__` already defaults `credit_case` and only touches it in
   the one print at `gpt.py:274` — so documents uploaded from the Customer page still get
   `file_type_name`, `extracted_data`, and a friendly filename, same as the credit-case flow.
2. `gpt.py:274`: guard that print with `if doc.credit_case:`.
3. `promote_csf_fields_to_customer`: resolve the customer via the same fallback, return early if
   there is none, and update the docstring (it currently asserts credit_case is required). The
   CSF → customer `rfc`/`legal_name`/address auto-fill then works from the Customer page too.
4. `storage/views.py`: wrap the per-doc side-effect loop in `try/except`, logging the failure and
   continuing. The `UploadDocument` row is already committed at that point, so an OpenAI outage
   should not turn a successful upload into a 500.
5. `UploadDocumentSerializer.validate` (`serializers.py:49-56`, currently a no-op with the old check
   commented out): reject a payload with neither `credit_case` nor `customer` with a
   `ValidationError` → a clear 400 instead of a mystery. This implements the `TODO` at
   `storage/models.py:112`.
6. `UploadDocumentViewSet.organization_lookup = 'customer__organization'` (`views.py:31`) hides
   credit-case-only documents from non-superusers — the `TODO` on that same line. Override
   `get_queryset` to `filter(Q(customer__organization__in=orgs) | Q(credit_case__customer__organization__in=orgs))`.

**Tests.** `backend/storage/tests/views_serializers/test_document.py` is entirely `@unittest.skip`ped
as stale, so there is no live coverage of this endpoint. Add:
- `test_upload_customer_only.py` — POST with `customer` and no `credit_case` returns 201 (mocking
  `storage.views.handle_upload_document_created`, matching the skipped file's existing pattern), and
  POST with neither returns 400.
- A service test that a customer-only CSF promotes `rfc`/`legal_name` onto the customer, alongside
  the existing `backend/storage/tests/services/test_promote_csf.py`.
