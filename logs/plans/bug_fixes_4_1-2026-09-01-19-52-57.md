# Plan — bug fixes 4/1

Logged 2026-09-01 19:52:57. Prompt: `logs/prompts/bug_fixes_4_1-2026-09-01-19-52-57.md`.

## The shape of it

Six of the seven items are two features wearing different clothes:

- **"Let me arrange this the way I work."** Column order and visibility on the dashboard;
  field order in the Details section. Same problem, so one library — `lib/layoutPrefs.ts` —
  rather than two.
- **"Stop making me retype what you already know."** The custom field value dropdown, and the
  verdict deadline placeholder carrying the organization's real number instead of the words
  "Organization default".

## Backend — USD

`CurrencyName` gains `USD`. A choices change produces an `AlterField` migration with no DDL
behind it, so this is not a schema change, but the migration has to exist or
`makemigrations --check` fails. The frontend list moves to `CURRENCY_OPTIONS` in
`lib/constants.ts` so the two selects that offer it cannot drift apart.

## `lib/layoutPrefs.ts` (new)

`{ order, hidden }` per list id, in localStorage beside `columnWidths.ts` and for the same
reasons. Pure functions so the interesting decisions are testable without a DOM:

- `applyOrder` — saved order first, then anything the saved order has never seen, appended.
  That is what makes "create a custom field and it shows up as a new column at the end" true
  even for a user who rearranged their columns months ago. An id that no longer exists is
  skipped, so a deleted field leaves no phantom column.
- `moveItem` / `nudgeItem` — drop-onto-target and one-step-at-a-time. Both take the CURRENT
  rendered order, not the stored one, because the stored order is allowed to be partial.

## Dashboard columns

`CreditCaseTable` gains ordered/visible column lists derived from the layout. Filters and
sorts run over the VISIBLE columns only — a filter on a column the user has hidden would
quietly remove rows with nothing on screen to explain why.

Two ways to rearrange, deliberately:

- Dragging a heading (`TableColumnHeader` gets HTML5 drag handlers; the heading text is the
  handle, so it does not compete with the sort button, the filter button or the resize edge).
- A `ColumnSettings` menu with checkboxes and Move up/down. Not a nicety: dragging is
  mouse-only, and a hidden column has no header left to click, so this is the only way back.

The last visible column cannot be switched off.

## Details section

The section held three visual languages for one idea — read-only tiles, form controls, and a
separate Custom fields panel further down the page. Now one list of `DetailField` cards, all
the same shape, all draggable, order saved under `creditCaseDetails`.

- `DetailField` / `DetailValue` — the card and the read-only value, the latter padded to match
  a form control so the two line up.
- `InfoTip` — one component, two jobs: the blue "custom field" marker, and the deadline
  explanation that used to be a paragraph making that card twice the height of its neighbours.
- Custom fields join the section's existing Save button. A per-card Save would have been the
  one thing in the section that did not look like everything else — so `hasUnsavedChanges`
  and Discard have to cover them too, and the case is re-read after the label writes because
  the PATCH response was serialised before them.
- `+ Add field` creates a Label inline, validated client-side first (the backend's unique
  constraint surfaces as a generic 400 that reads badly).

## `ValueCombobox` (new)

A `<datalist>` shows nothing until you type, so an existing "MTY Norte" was undiscoverable and
got retyped as "MTY norte" — two unrelated values on the dashboard. This is a real dropdown
that is still a free-text box, because the first case to use a new value has to type it. No
caret at all when the field has no values yet. Portal-positioned `fixed`, like every other
panel in this app.
