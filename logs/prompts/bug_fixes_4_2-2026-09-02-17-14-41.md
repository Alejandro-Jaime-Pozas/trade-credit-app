## What the report actually describes

The premise is a misconception, and that is the finding: **there is no page that creates custom
field values.** `/labels` creates, renames and deletes the FIELDS; a value exists the moment a
case is saved with it. Typing a new value in the credit case detail page already worked.

So nothing was broken in the sense of a failing write. What was broken is that the control gave
no sign of it. Yesterday's `ValueCombobox` (bug 4/1, item 1) lists the values already in use,
and a list of existing values reads as the set of permitted answers — so users went looking for
somewhere else to define one.

Fixed as an affordance problem: make "you may type a new value" visible rather than merely true.
