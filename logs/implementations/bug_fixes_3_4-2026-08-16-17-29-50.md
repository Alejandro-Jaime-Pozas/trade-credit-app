## Item 1 — success popups now disappear on their own

### New — `frontend/src/lib/useTransientMessage.ts`

`useTransientMessage(durationMs = TRANSIENT_MESSAGE_MS)` returns `{ message, show, clear }`.

- `show(text)` displays and starts a 4000ms countdown; calling it again replaces the pending
  timer rather than leaving two racing to hide different messages.
- `clear()` hides immediately (used where the old code already cleared the message: starting
  a save, discarding changes, undoing a template save, unlinking a customer).
- The timer id lives in a ref, cancelled on unmount, so a fired timeout can never set state
  on an unmounted page.
- The timeout is scheduled inside `show`, never in a `useEffect` — `set-state-in-effect`.

### Changed — the four pages that showed a confirmation

| --- | --- | --- |
| `src/app/customers/[id]/page.tsx` | `const [saved, setSaved]` | `const { message: saved, show: showSaved, clear: clearSaved }` |

| `src/app/requirements/page.tsx` | same (3 messages) | same |

Left alone on purpose: **every error banner** (an error must be read and acted on), and the
green "✓ linked customer" panel on the new-credit-case wizard — that is persistent state
saying which customer the case is for, not a confirmation.

## Item 2 — documents can be renamed and deleted

### Backend

**`backend/storage/serializers.py`**
- `friendly_file_name` removed from `read_only_fields`, with a comment explaining why it is
  writable and why `original_title` is not.
- New `validate_friendly_file_name`: strips whitespace and turns a blank value into `None`,
  so "no friendly name" is one database state rather than two.

**`backend/storage/views.py` — `UploadDocumentViewSet.perform_destroy` (new)**
- Reads the linked credit case, deletes the document, then calls
  `handle_manual_requirement_change(credit_case)`.
- Rationale (also recorded in `docs/architecture/decisions.md`): `requirements_complete` is
  computed from the documents that exist right now, so deleting one can un-satisfy a
  requirement. Without the recompute, deleting the only bank statement leaves the case in
  `pending_final_verdict` — in a reviewer's queue with the evidence gone.
  `handle_manual_requirement_change` (not `handle_requirements_progress`) because this is a
  user deliberately removing something from one case, so pulling the case BACK is correct.

**Multi-tenant:** no new surface. `UploadDocumentViewSet.get_queryset()` already scopes to
`customer__organization` OR `credit_case__customer__organization`, so PATCH and DELETE on
another organization's document 404 before any of the above runs. Covered by two tests.

**`backend/schema.yaml` + `frontend/src/lib/api.generated.ts`** — regenerated via
`./scripts/sync-api-schema.sh`; `friendly_file_name` is no longer `readOnly`.

### New — `backend/storage/tests/views_serializers/test_document_rename_delete.py` (9 tests)

Rename persists · `original_title` untouched by a rename · blank name clears to `NULL` ·
whitespace trimmed · another org's document cannot be renamed (404, unchanged) · delete
works · another org's document cannot be deleted (404, still exists) · deleting the
satisfying document pulls the case back to `missing_documents` · deleting an unrelated extra
document leaves a still-complete case where it is.

### Frontend

**`frontend/src/components/DocumentList.tsx`**
- New exported `documentDisplayName(doc)` — friendly name if set, else `original_title`, else
  "Untitled document". Exported because both detail pages need it for their delete dialogs.
- The original file name is still rendered in the row's metadata line whenever a friendly
  name is hiding it, so the user can always tell which actual file a row is.
- New optional props, matching the existing "no handler, no control" convention:
  `onRename(doc, friendlyName | null)`, `renamingUrl` (per-row spinner), `onDelete(doc)`.
- Rename is inline: a Rename button swaps the title for a text box seeded with the current
  display name, with Save / Cancel; Enter saves, Escape cancels. Submitting an unchanged
  name fires nothing. Emptying the box sends `null`, which restores the original file name.
- Delete only raises the request — the page owns the confirmation, matching how customers,
  contacts and requirements already work.
- Download / Rename / Delete now sit together on one action row.

**`frontend/src/app/credit-cases/[id]/page.tsx`**
- `handleRenameDocument` — PATCH `friendly_file_name`, swap the row in place. No case
  re-read: a display label cannot move the requirement checklist.
- `handleDeleteDocument` — DELETE, then `reloadCaseAndUploads`, because the backend may have
  just moved the case back to "missing documents".
- `ConfirmDialog`: "Delete this document?" · "If this file was satisfying a required
  document, this case goes back to missing it."

**`frontend/src/app/customers/[id]/page.tsx`**
- Same rename handler; delete simply drops the row from state (a customer-only document has
  no case status to recompute).
