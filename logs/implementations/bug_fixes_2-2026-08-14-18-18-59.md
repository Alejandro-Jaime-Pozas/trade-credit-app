## Backend

### `verdict` is writable (`processing/serializers.py`)
`verdict` was in `read_only_fields`, so the detail page could display a decision but never record
one. Removed from that list. Added `CreditCaseSerializer.update()` to stamp `verdict_at` when the
verdict actually changes — the timestamp records *when* the decision was made, so it isn't the
client's to set. Moving back to `pending` clears it, since there is no longer a decision for it to
be the time of.

### Signup enforces a password minimum (`identity/serializers.py`)
`settings.AUTH_PASSWORD_VALIDATORS` was configured but never consulted: DRF treats `password` as a
plain CharField, and those validators only run through Django's own auth forms, which this API never
touches. A one-character password was accepted. Added `UserSerializer.validate_password()` calling
`django.contrib.auth.password_validation.validate_password`, translating Django's ValidationError
into DRF's so it returns a normal 400 field error.

### `file_type_name` is correctable (`storage/serializers.py`)
GPT classification is fallible, and a mislabelled document silently fails to satisfy the requirement
it should. Removed from `read_only_fields` and added `validate_file_type_name()`, which only accepts
keys in the catalog the requesting user can see (global + their own orgs) plus `unknown`. Free text
would be worse than a wrong label — requirements match on this exact key, so a typo produces a
document that can never satisfy anything. On create the field is still effectively read-only, since
classification runs after save and overwrites whatever was sent.

**Bug found on the way:** `UploadDocumentSerializer.validate()` read `credit_case`/`customer` from
`attrs` only, so **every** PATCH was rejected as "missing customer/credit_case" — a partial update
doesn't resend unchanged fields. It now falls back to the instance being edited.

## Frontend

### Every Delete button reported failure on success (`lib/api.ts`)
`apiJson` always called `res.json()`. DRF answers a successful DELETE with `204 No Content`, so the
empty body threw a SyntaxError that surfaced as "Delete failed" — on a delete that had worked. Added
`readJsonAllowingEmpty()`: a 204 or empty body resolves to `undefined`. This fixes every delete in
the app at once (credit case, customer, contact, requirement), which is what the report suspected.

### New shared components
- **`Spinner.tsx`** — the loading ring, `aria-hidden` (surrounding text does the announcing).
- **`StatusDot.tsx`** — coloured dot per status: complete green, missing documents orange, buró
  rejected red, pending final verdict yellow, and **pending AI verdict as a spinner** since that is
  the one status where work is actively happening. Colour is never the only signal — the dot always
  sits beside the status text and carries its own accessible name.
- **`Modal.tsx`** — the dialog shell. Escape, a ✕, and backdrop click, wired once. Modals previously
  hand-rolled their markup and none listened for Escape.
- **`FileUploadField.tsx`** — choosing files IS the upload instruction; no Upload button. Spinner and
  the filenames while in flight, inline error with a retry. The input is cleared after each
  selection so re-picking the same file still fires, which is what makes retry work.
- **`FileTypeSelect.tsx`** — searchable single-select for correcting a document's type, with
  `unknown` always offered as a way back.
- **`DocumentList.tsx`** — uploads rendered as bordered rows matching the Required documents
  checklist they sit beside, **newest first**, with the type either a plain badge or the editable
  combo.
- **`CreditCaseTable.tsx`** — the whole dashboard table (columns, sorting, filtering) extracted from
  `credit-cases/page.tsx` so the customer detail page can show the same columns. Sharing the
  component is what stops the two drifting apart. `credit-cases/page.tsx` is now a thin loader.

### Credit case detail (`credit-cases/[id]/page.tsx`)
- Verdict is now an editable select beside Status and Assigned to; the read-only Verdict box became
  a "Decided" timestamp. Status select shows its dot inline.
- Save confirms with an `aria-live` "Saved." — previously the only feedback was the spinner stopping.
- `applyCase()` centralises putting a fetched case on screen *including the form-bound state*.
  Setting only `creditCase` left the Status/Verdict selects showing stale values, which is how an
  upload that advanced the case ended up needing a page reload to be visible.
- `reloadCaseAndUploads()` re-reads case + uploads + requirements together after any upload or
  relabel, so completing the last required document updates the status without a refresh.
- Uploads use `FileUploadField` and `DocumentList`; the Upload button is gone.

### Customer detail (`customers/[id]/page.tsx`)
- New **Credit cases** section using the shared `CreditCaseTable`, newest first, same columns as the
  dashboard.
- **Uploads → Documents**, rendered with the same `DocumentList` as the credit case page, with
  auto-upload and file type correction.
- Save confirms with "Saved.".

### Requirements page (`components/ImpactWarning.tsx`)
Rebuilt on `Modal`, so Escape/✕/backdrop all dismiss it. The ambiguous "Keep them as they are" is now
"Cancel — keep them as they are". Dismissing means "leave open cases alone", which is the safe
answer: the default list is already saved by the time the dialog appears.

### Generated API types
Ran `scripts/sync-api-schema.sh`. `api.generated.ts` was substantially stale relative to the backend
(from earlier backend work that didn't regenerate it), so the diff is large — but `verdict` and
`file_type_name` are correctly no longer `readonly`.
