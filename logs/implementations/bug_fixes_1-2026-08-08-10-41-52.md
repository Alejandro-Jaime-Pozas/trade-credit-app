# Implementation Log — bug_fixes_1 — 2026-08-08

Fixes for `docs/bug_fixes/1/1.md`. Plan: `logs/plans/bug_fixes_1-2026-08-06-19-43-10.md`.

## 1. Signup buttons not working

Root cause turned out to be broader than the visual issue first suspected — three
separate defects stacked on the same path:

- **`backend/app/mixins.py`** — `OrganizationScopedMixin.get_queryset` now returns
  `queryset.none()` for unauthenticated requests instead of crashing on
  `AnonymousUser.organizations` (`AttributeError` → 500). This affects every
  `OrganizationScopedMixin` viewset, not just users.
- **`backend/identity/views.py`** — `UserViewSet.permission_classes = [AllowAny]`
  replaced with `get_permissions()`: `AllowAny` only for `action == "create"`
  (signup), `IsAuthenticated` otherwise. `GET /users/{id}/` (the 3rd call in the
  signup chain) now requires the token it already sends; previously it 500'd for
  *any* anonymous caller because of the mixin bug above.
- **`frontend/src/components/AppShell.tsx`** — the header "Sign up"/"Log in" pills
  are now hidden on `/signup`/`/login` respectively (`pathname` check), since they
  previously just re-linked to the page you were already on.
- **`frontend/src/lib/api.ts`, `lib/auth.tsx`, `app/login|signup/page.tsx`** — added
  `logError()` and a `safeFetch()` wrapper that turns a raw
  `TypeError: Failed to fetch` into an `ApiError` naming the API base URL, wired
  into every catch block that was previously silent.
- **Deleted `frontend/.next`** (user-approved) — live investigation found `/signup`
  specifically hung forever mid-compile under Turbopack (confirmed via verbose
  curl: connection established, zero bytes ever returned; repeated across several
  dev-server restarts in the container's log history) while every other route
  compiled and served fine concurrently. The stale `.next` (last full build from
  Jun 13, containing duplicate/orphaned chunk files for `signup` since) was almost
  certainly the actual cause of "neither signup button is working" — a plain dead
  link would still show *something*, not hang the tab. Deleting it and letting
  Turbopack regenerate fixed the hang immediately (`/signup` now `200` in <1s).

## 2. Customer combobox has no keyboard support

`frontend/src/app/credit-cases/new/page.tsx` — added `activeIndex` state and a
`dropdownOptions` list (matching customers + trailing "create new" row).
`onKeyDown` on the search input: ArrowUp/ArrowDown move the highlight with
wraparound, Enter/Tab commit the highlighted option, Escape closes. Replaced the
`setTimeout(..., 150)` blur hack with an `onBlur` on the wrapper div that checks
`relatedTarget` containment. Added `role="combobox"`/`listbox`/`option` +
`aria-activedescendant` for screen readers. Mouse hover keeps `activeIndex` in
sync so keyboard and mouse never disagree.

(One follow-up mid-verification: the first version reset `activeIndex` via a
`useEffect` keyed on `search`, which the project's `eslint-plugin-react-hooks`
flagged — "Calling setState synchronously within an effect". Moved the reset
into the `onChange` handler directly; lint is clean.)

## 3. REQUESTED column not comma-formatted

New `frontend/src/lib/format.ts`: `formatMoney(amount, currency)` using
`Intl.NumberFormat("es-MX", { style: "currency", currencyDisplay: "code" })` →
`"MXN 7,895,432.00"` (falls back to a plain grouped number + raw code if the
currency code is malformed). Wired into `credit-cases/page.tsx`'s Requested
column. Also moved the file's local `formatDate` there and deduped the three
other copies of the same function (`credit-cases/[id]/page.tsx`,
`customers/[id]/page.tsx`, `customers/page.tsx`) to reuse it.

## 4. Upload fails from the Customer detail page

- **`backend/storage/services/db_object_handling.py`** —
  `handle_upload_document_created` now requires *either* `credit_case` or
  `customer` (was: `credit_case` only, raising `ValueError` otherwise → 500).
  `promote_csf_fields_to_customer` resolves the customer via
  `doc.customer or doc.credit_case.customer` and no-ops if neither exists.
- **`backend/integrations/openai/services/gpt.py:274`** — guarded the
  `doc.credit_case.missing_file_type_names` print with `if doc.credit_case:`
  (would `AttributeError` on a customer-only doc otherwise).
- **`backend/storage/views.py`** — `UploadDocumentViewSet.create()`'s per-doc
  side-effect loop is now wrapped in `try/except` + `logger.exception`, so a GPT/
  OpenAI failure can't turn a successful upload into a 500 (the request runs
  inside one atomic transaction — `ATOMIC_REQUESTS: True` — so an uncaught
  exception here would have rolled back the already-saved `UploadDocument` too).
  Replaced the single-relation `organization_lookup` with a `get_queryset()`
  override that matches on customer's org OR credit_case→customer's org, so
  credit-case-only docs are no longer invisible to non-superusers (pre-existing
  `TODO` at `views.py`).
- **`backend/storage/serializers.py`** — `UploadDocumentSerializer.validate()`
  (previously a no-op, old check commented out) now rejects a payload with
  neither `credit_case` nor `customer` with a 400.
- **Tests**: `storage/tests/views_serializers/test_upload_customer_only.py` (new)
  — customer-only upload → 201; neither field → 400; a side-effect exception
  still returns 201 with the doc saved; credit-case-only upload still works
  (regression guard). `storage/tests/services/test_promote_csf.py` — added a
  customer-only CSF promotion test and a no-customer/no-credit_case no-op test.
