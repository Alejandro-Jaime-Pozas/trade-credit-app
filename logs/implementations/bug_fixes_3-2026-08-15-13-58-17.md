# Implementation — `docs/bug_fixes/3/3.md`

Date: 2026-08-15

Seven frontend items, no backend changes.

## 1. New credit case wizard redirects straight to the case

`app/credit-cases/new/page.tsx` — step 3 used to end on a confirmation panel with a
"Go to credit case" button. That screen carried no decision, so it was a second click for nothing.
A new `goToCreditCase()` runs on every successful path, and the interstitial (and the
`requirementsOutcome` state behind it) is gone. When replacing the org default surfaces the impact
dialog, the redirect waits until the user answers it.

## 2. Uploads survive navigation

**New `lib/uploadTracker.ts`** — a module-scope store of in-flight uploads, grouped by `scope`
(a credit case or customer URL). It OWNS the upload promise, so the request keeps running when the
component that started it unmounts, and the "Uploading…" state is still there on return.

`FileUploadField` reads it through `useSyncExternalStore`. The snapshot per scope is cached and
only rebuilt on change — returning a fresh object per read would loop forever rather than fail
visibly. Both detail pages pass `scope` and an `onBackgroundUploadsSettled` callback, so an upload
that finishes while nothing is awaiting it still refreshes the page.

Deliberately not persisted to storage: a full page reload tears down the fetch too, so a remembered
"still uploading" flag would be a lie. This covers client-side navigation, which is what was broken.

## 3. Discard changes on detail pages

Both detail pages gained a `Discard changes` button beside Save, plus a `hasUnsavedChanges` check
that disables it when there is nothing to lose. Each page has a `…FormValues(source)` helper giving
the controls' values straight from the loaded record, used by both the comparison and the reset, so
the two can't disagree about what "unchanged" means.

## 4. AI notice per section

**New `components/AiNotice.tsx`** — "AI can make mistakes, make sure the data created is accurate."
Placed once per section rather than per field: repeating a caveat on every input is noise a user
learns to skip, and it implies the untouched fields are somehow different.

Shown on the customer Profile section (CSF extraction fills rfc/zip/street) and at the top of
`DocumentList` (every row's type was assigned by the classifier).

## 5. Impact modal now has three buttons

`components/ImpactWarning.tsx` — **Cancel**, **Keep them as they are**, **Update these cases**, and
Escape / ✕ / backdrop now map to **Cancel**, not Keep.

That required a real behaviour change, not just a button: the template is written *before* the
impact can be computed (the backend compares against the stored template), so Cancel has to be an
undo. Both call sites now capture the template's file type ids before saving and PATCH them back
when the user cancels. Without that, dismissing the dialog silently left a default the user never
agreed to.

## 6. Requirements page no longer holds a stale selection

`app/requirements/page.tsx` — the chooser was keyed by the saved template's ids, so cancelling a
save (which now reverts the template) would have wiped the user's selection off the screen mid-edit.
It is now keyed by an explicit `chooserResetKey` that the page bumps only when the chooser should
resync with what is saved — after Apply and after Keep, but **not** after Cancel, since someone
backing out is usually still deciding. Leaving the page needs no bump: the page unmounts and
re-reads the template on return, so an unsaved selection never survives navigation.

## 7. Resizable, remembered column widths

Confirmed with the user: "lengths" means column widths, persisted in this browser.

**New `lib/columnWidths.ts`** — load/save per table id in localStorage, with clamping to
80–900px. The loader drops anything unparseable or out of range rather than trusting it: a corrupt
entry would otherwise render a permanently broken table with no way back.

`TableColumnHeader` gained a `role="separator"` grip on the column's right edge:
- drag tracked on `document`, not the handle, so the pointer leaving the thin grip mid-drag
  (which it always does) doesn't stop the resize;
- arrow keys resize too (Shift for bigger steps), so it isn't mouse-only;
- double-click clears the stored width and lets the table size the column again.

`CreditCaseTable` loads widths lazily on first render — an effect would paint at default widths and
then snap, and `react-hooks/set-state-in-effect` rejects the synchronous setState that would avoid
that. Widths are persisted once on release, not per pixel, and the drag's listeners read the latest
widths through a ref because they close over the render at pointer-down.

## Tests

Frontend **201 passed** (was 175). Backend unchanged at 174 passed / 6 skipped.

- `lib/uploadTracker.test.ts` (8) — counting, release on success AND on failure, scope isolation,
  concurrent uploads, subscriber notifications, and the stable-snapshot contract
  `useSyncExternalStore` depends on.
- `components/FileUploadField.test.tsx` (+3) — the reported bug directly: start an upload, unmount,
  remount, and the indicator plus filenames are still there; the settled callback fires for uploads
  nothing awaited; another scope's uploads are not shown.
- `lib/columnWidths.test.ts` (8) — round-trip, per-table isolation, corrupt JSON, non-numeric
  entries, and clamping of out-of-range stored values.
- `components/TableColumnHeader.test.tsx` (+7) — drag reports widths and persists once on release,
  tracking stops on release, the minimum is respected, keyboard resizing, and double-click reset.

`vitest.setup.ts` gained a `PointerEvent` polyfill: jsdom doesn't implement it, so
`fireEvent.pointerDown` built a plain Event and `clientX` never reached the handler, making every
drag look like a drag to NaN.

`npx tsc --noEmit` and `npm run lint` clean. All six affected routes return 200 with no dev-server
errors.
