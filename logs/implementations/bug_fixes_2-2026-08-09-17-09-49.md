# Implementation — bug fix batch 2 (`docs/bug_fixes/2/2.md`)

Date: 2026-08-09
Plan: `logs/plans/bug_fixes_2-2026-08-09-17-09-49.md`

Frontend only; no backend changes. All three defects were in code added earlier the same day by
`credit_cases_column_filter_sort`.

## 1. Filter dropdown cut off on the left

**Cause.** The panel was `absolute right-0` inside the header cell, and the table sits in an
`overflow-x-auto` wrapper. A scroll container clips its descendants, so on the leftmost sortable
column (CUSTOMER) the 16rem panel was sliced at the table's left border — the "n customer…" /
"ee Broomsticks" truncation in `image.png`.

**Fix** (`frontend/src/components/TableColumnHeader.tsx`): the panel now renders through
`createPortal` into `document.body` with `position: fixed`, so no ancestor can clip it.

- `computePanelPosition(button)` measures the filter button with `getBoundingClientRect()`,
  right-aligns the panel to it, then clamps `left` into the viewport with an 8px margin — which is
  what stops the leftmost column running off the edge.
- The option list's `max-height` is derived from the space actually below the button instead of a
  fixed `max-h-64`, so the panel can't hang off the bottom either.
- Position is computed in the open handler (not in an effect), so the panel is correct on its first
  paint and no `setState` happens inside an effect body
  (`react-hooks/set-state-in-effect`).
- Repositioned on `resize` and on `scroll` in the capture phase, so the table's own horizontal
  scrolling is tracked, not just the window's.
- The old wrapper `onBlur` containment check can't see a portalled panel, so closing is now handled
  by document-level `mousedown` + `focusin` listeners that check the event target against both the
  button and the panel. Registered only while open, removed on cleanup.

## 2. Buttons too small / arrow cursor instead of a hand

- `frontend/src/app/globals.css`: added `button:not(:disabled) { cursor: pointer; }`. Tailwind v4's
  preflight dropped the old default, so this was affecting **every** button in the app, not just the
  reported page — the user confirmed an app-wide fix. Disabled buttons are excluded so the cursor
  doesn't promise an interaction that won't happen.
- `TableColumnHeader.tsx`: the sort button is now a `h-7 w-7` centred box with a `text-sm` glyph, and
  the filter button `h-7 min-w-7` with an `h-4 w-4` icon (previously `px-1 text-xs` with an `h-3 w-3`
  icon). Dropdown option rows went `py-1.5` -> `py-2`, and the search input and Clear button got
  matching padding.

## 3. Customer column links to the credit case

`frontend/src/app/credit-cases/page.tsx`: the Customer cell's `<Link>` now targets
`/credit-cases/${cc.id}` instead of `/customers/${cust.id}`. Customer detail pages remain reachable
via the Customers item in the `AppShell` nav, so nothing is orphaned.

## Observation, not acted on

`globals.css` flips `body` to a dark background under `prefers-color-scheme: dark`, but every
component hardcodes light colours (`bg-white`, `text-zinc-900`). The app therefore has no real dark
mode. The dark appearance in `image.png` looks like Chrome's auto-dark page inversion rather than
app styling. Pre-existing and outside this bug report.
